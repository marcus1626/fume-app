## Layers
1. **Brand primitives** `tokens/fume-tokens.css|json` (v1.3, approved): the palette, type scale, spacing, Focus System values.
2. **UI tokens** `design-system/tokens/ui.tokens.json` → `ui.css` (`--ui-*`) and `ui.resolved.json`: roles and states (ground, surface, text, action hover and pressed, glass, radius, space, inset, motion). Every value points at a primitive. Build with `node tools/tokens/build.mjs`; never edit `ui.css` by hand.
3. **Components** `design-system/components/*.css` (one file per component or tight family; behaviour, where needed, in a small `<name>.js` that initialises from data attributes): use only `--ui-*` tokens. Foundations: `base.css` (load first: no grey tap box, `touch-action`, 16 px fields on touch), `glass.css`, `touch.js` (lets iOS show the pressed state), `focus.js` (the focus ring only for the keyboard: a field you click or tap into shows its caret, Marcus 13 Oct). Round 7 families: fields (`field`, `input-group`, `select`, `input-otp`, `kbd`), choices (`choice`, `checkbox`, `radio`, `switch`, `slider`, `toggle`, `button-group`, `badge`, `spinner`, `progress`), glass layers (`dialog`, `sheet`, `popover`, `tooltip`, `toast`, `context-menu`, `command`, `combobox`, with `menu`), content (`card`, `creative`, `item`, `avatar`, `alert`, `empty`, `skeleton`, `accordion`, `scroll-area`, `separator`, `data-list`), navigation and data (`sidebar`, `nav`, `breadcrumb`, `pagination`, `tabs` on `segmented`, `table`, `calendar`, `carousel`). Round 8: the upload box (`dropzone`), Engine and chat (`message` with bubble and scroller, `composer`, `run`, `attachment`, `marker`), charts and numbers (`chart`, `stat`), layout and tools (`menubar`, `resizable`, `toolbar`, `stepper`, `page-header`, `settings`, `filter-bar`), Fume screens (`qg-review`, `viewer`, `notify`, `share`, `onboard`). Round 10: shimmer text (`text-shimmer`). Status per component in `components.md`.
   Component tokens live in `design-system/tokens/components/<family>.tokens.json`, in the same format as `ui.tokens.json`; the token build merges them into `ui.css` (a group name used twice is a build error).
4. **Icons** `design-system/icons/`: filled Lucide plus Fume's own icons, generated by `node tools/icons/build.mjs` from `tools/icons/icons.mjs` (sprite, single SVGs, manifest). See `design-system/icons/README.md`.
5. **shadcn bridge** `design-system/theme/shadcn.css`: maps shadcn's variable names (`--primary`, `--popover`, `--ring`, …) to UI tokens, so shadcn/ui React components pick up the brand. Load order: primitives, `ui.css`, bridge.
6. **Web kit** `kit/` (PROPOSED, 13 Oct): the page layer for websites and other Fume pages in HTML (`kit/web.css`: sections, marketing titles in Canon, the brand light, the statement on Brown, images with the Focus frame and grain), on its own token family `web` (`tokens/components/web.tokens.json`) and the type tokens `display-hero` and `display-small`. `node kit/build.mjs` bundles it with the fonts, the primitives, the UI tokens it uses and the base, button, badge, card and separator into one stylesheet and one script (`kit/dist/`); the connector serves the same with `fume_get_kit`. Guide: `kit/README.md`. The landing page template `templates/web-page` is built with it and nothing else.

## Principles (DECIDED 13 Oct)
- Calm ground, sharp decisions: Porcelain carries the page, Ink makes the decisions.
- States come into focus: on light surfaces hover is one step toward Ink on the Focus ramp, pressed is two plus a 3 % shrink on pointer-down. Ink lifts one step on hover and returns when pressed. No hue changes.
- Layers, not lines: regions are separated by surface (`--ui-ground-behind`, `--ui-surface`), depth (`--ui-depth-raised`, `--ui-depth-sheet`) and space. A sidebar sits on the layer behind; the page lies on it as a sheet. Hairlines only where something would vanish (inputs, the white secondary button, the creative's edge). Gate rule `few-strokes`.
- Floating layers are Smoke glass (DECIDED): Ink 28 % over a blurred, softened, dimmed backdrop, no stroke, an Ink-tinted shadow under the glass. Main action on glass is a white button (94 %) or a coloured one at 80 % (Rouge for delete, 90 % on hover); the rest are clear with a 10 % veil; no shadow on any.
- Menu rows fill the menu edge to edge, with no inset or radius of their own. Tabs and segmented controls slide the selection.
- Amber is a point: the check landing, as a point or the checked triangle beside a label. Amber when an expert has checked the work, grey while it is in check. The expert checks; only the customer approves. One per view in brand compositions; in product UI every approved creative shows its own.
- GT Standard for all UI. GT Canon only for marketing titles. Mono only for data.
- Pills for actions (buttons, chips, badges, tabs, segmented controls, floating bars), DECIDED; soft rectangles for content (fields 12, list rows 10, cards 16). Floating layers: menus and popovers 22 (`--ui-radius-float`), dialogs and sheets 32 (`--ui-radius-panel`), DECIDED.
- Touch: every control is 44 px to a finger (`--ui-size-hit`, an invisible hit area on small controls), a tap shows the pressed state, hover only with a mouse. Measured on the rendered board in CI.
- Air: every surface takes its padding from `--ui-inset-*` (panel 24, float 16, tight 12, ring 6); text never sits closer to an edge than three quarters of the corner radius. Gaps and margins come from `--ui-space-*`.
- Proximity: the space between groups is at least twice the space inside a group (label 8 above its field, fields 24 apart; a name 8 above its example, examples 32 apart). Review rule `proximity`, round 7.
- No gradients, with one exception: shimmer text (`text-shimmer.css`), a band of white light through dark words that are under way, the Engine's included (its Amber variant was taken out 15 Oct: "amber shimmer var ikke fint"), each gradient line marked `gate-allow:no-gradient` (round 11, approved 13 Oct). Skeletons pulse between two flat colours, a little out of step (round 7 look; the round 8 skeleton shimmer was too artificial).
- Big numbers (stat tiles, a donut's total) are GT Standard with tabular figures; mono stays small: ticks, dates, sizes, times, codes.
- Icons: filled Lucide (DECIDED); line-only icons at 2.25. Fume's own icons on Lucide's grid: the checked triangle and the Engine for AI (DECIDED).

## Rules and gate
`rules/ui.rules.json` holds 45 rules. `node tools/gate/gate.mjs` checks the 31 automatic ones (three of them, the copy rules words-avoid, name-the-actor and no-exclamation, run only on copy sent to `fume_check` and on template content) on components, component tokens, themes, the review board and its sections, `site/`, `packages/`, `templates/` and the web kit (`kit/`); the 14 review rules are checked by eye before work is shown. Rules marked `measured` are also measured on the rendered page: `node tools/gate/audit.mjs` (needs Playwright) renders the built review board on a 390 px phone and at 1280 px and checks hit areas, tap flash, field text and air; `node tools/gate/audit-test.mjs` is its self-test. CI runs both in the `render-audit` job, and also audits the landing page template built from the kit. `node tools/gate/test.mjs` proves the gate still catches each rule. CI (`.github/workflows/gate.yml`) runs all three and checks that the built tokens and icons are up to date. To break a rule on one line on purpose, add a comment with `gate-allow:<rule-id>` and the reason.

## Adding a component
1. Read the shadcn source for its API (variants, sizes, parts). Keep the API, redesign the look.
2. Missing a role or state? A shared role goes in `ui.tokens.json`, a component's own value in its family's `tokens/components/*.tokens.json` (PROPOSED); run the token build.
3. Write `components/<name>.css` with `--ui-*` tokens only, every state (hover, pressed, focus, disabled, loading where it applies) and a reduced-motion block. Anything you can press gets a 44 px hit area, a pressed state and hover inside `@media (hover: hover)`; the gate checks all three.
4. Run the gate, put it on the review board (a section file in `review/sections/`, see `review/README.md`), build it and run the render audit, then look at it on a phone and a desktop and check it against `docs/RULES.md`.
5. Commit when Marcus approves, with the approval in the message. Track progress in `components.md`.
